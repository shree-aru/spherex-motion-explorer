Image Header DescriptionThe header of a spectral image file encodes key metadata used for identifi-
cation, calibration tracking, and scientific analysis. Key fields include the observation ID, detector number,
product creation time, exposure start time (in UTC), and total exposure duration. Astrometric metadata,
such as coordinate system definitions and optical distortion parameters, are also recorded to support accurate
spatial registration. Each file header contains unique identifiers for the calibration products applied during
processing, along with an approximate mapping between pixel coordinates and their corresponding cen-
tral wavelengths. Additional metadata relevant to downstream analysis includes spacecraft and instrument
parameters – for example, mean detector array and telescope mirror temperatures during the exposure.
The header also includes information on the planned pointing for the telescope boresight (SPS LON ECL,
SPS LAT ECL, andSPS PA ECL) in ecliptic coordinates as specified in the survey plan. These values are the
same for all 6 bands in each observation. TheSPS PA ECLkeyword can be used to determine which survey
a given observation belongs to:
•Fromt= 0 to 12.5 months, all-sky data taken with PA = 0 is Survey 1
•Fromt= 0 to 12.5 months, all-sky data taken with PA = 180 ◦ is Survey 2
•Fromt= 12.5 to 25 months, all-sky data taken with PA = 0 is Survey 3
•Fromt= 12.5 to 25 months, all-sky data taken with PA = 180◦is Survey 4
The pointing targets for Surveys 3 and 4 are shifted by 6 ′ with respect to Surveys 1 and 2 to provide finer
spectral sampling.
The RA and DEC calculated per band as part of the astrometric calibration (Sect. 3.2.8) are available in
the standardCRVAL1andCRVAL2keywords. The header also records the full list of data processing modules
executed to generate the file, including associated software versioning. A representative header structure is
shown in Table A.35, with all entries specific to the illustrated example.
In spectral image files, the long-keyword convention (HIERARCH) 2, originally developed by the European
Southern Observatory (ESO), is used to support header keywords that exceed the standard 8-character
Flexible Image Transport System (FITS) limit. This convention ensures compatibility with automated
metadata parsing during file ingestion and analysis. TheIMAGEextension contains a WCS header that
provides an approximate pixel-to-wavelength mapping.

3.4 Mosaics
3.4.1 Overview
The SPHEREx pipeline has the ability to create image mosaics from SPHEREx Level 2 (L2) calibrated
spectral images. This processing combines multiple L2 images taken at different times and spacecraft ori-
entations to produce co-added images for each spectral channel. This capability is used within the Mosaic
Tool hosted by IRSA and for the all-sky data cubes which are part of the Year 1 and Year 2 Data Releases
(see Sect. 2.1). Currently, this document describes the functionality for the IRSA Mosaic Tool. The IRSA
Photometry Tool will continue to use the L2 calibrated images and does not use mosaics as input. For
science applications requiring precision photometry, we recommend using the L2 spectral images directly.
The mosaic creation process consists of the following high-level steps, each described in more detail below.
1. Query and load L2 spectral images covering the target region
2. Subtract the zodiacal light model (L2 image ZODI extension) from each image
3. Apply bad pixel masking based on quality flags (L2 image FLAGS extension)
4. For each spectral channel, extract pixels using a channel template (Sec. 3.4.4). The channel template
and pre-calculated channel statistics are available as the spectral channels calibration product.
5. Reproject extracted pixels to a common output grid
6. Accumulate weighted contributions from all images
7. Produce final averaged mosaic
3.4.2 Input Data
Each L2 FITS file contains data from one of the 6 detectors for a single exposure and includes IMAGE,
ZODI and FLAGS extensions, as described in Sec. 2.2.
For the initial release of the Mosaic Tool, only L2 images from the All-Sky Survey are included. Images
from Deep Field Surveys are excluded.
3.4.3 Data Loading and Preprocessing
When loading an L2 file, the tool performs the following steps:
1. Zodiacal Light Subtraction: The zodi-subtracted science image is computed as: data = IMAGE - ZODI
2. Bad Pixel Masking: Pixels with any of the following quality flags are set to NaN and excluded from
the mosaic (see Sec. 3.2.5 for definitions):
•TRANSIENT, SUR ERROR, NONFUNC, DICHROIC, MISSING DATA
•HOT, COLD, PHANMISS, NONLINEAR, PERSIST
•CROSSTALK, GHOST, GHOST FPA, GHOST EXT
•STREAK, BLOOM, SNOWBALL, HALO, SATELLITE HALO
3. Flag Propagation: The following flags are propagated to the output mosaic: OVERFLOW, SOURCE,
OUTLIER (see Sec. 3.2.5 for definitions).
